# Accessibility Baseline (Primitives)

This document defines non-negotiable accessibility rules for primitive components.

## ARIA Labels and Roles

- Interactive primitives must expose accessible names:
  - `Button`: visible text and optional `ariaLabel` override.
  - `Input`: pass `aria-label` or pair with a `<label htmlFor=...>`.
  - `Select`: pass `aria-label` or pair with a `<label htmlFor=...>`.
- `Modal` must expose dialog semantics with:
  - `role="dialog"`
  - `aria-modal="true"`
  - `aria-labelledby` and `aria-describedby`
- Status surfaces must expose live semantics where applicable:
  - `StatusBadge`: `role="status"`
  - `Toast`: `role="status"` and `aria-live="polite"`

## Keyboard Baseline

- `Tab` order follows DOM order and remains deterministic.
- Focus is trapped inside `Modal` while open.
- `Escape` closes `Modal`.
- Shift+Tab loops within `Modal` focusable controls.

## Focus Visibility

- Interactive primitives use token-driven visible focus ring via `.kp-primitive-focus`.
- Focus ring uses `--color-signal` and must remain visible against dark surfaces.

## Quality Gate

- Accessibility tests must cover:
  - semantic role/label presence
  - modal keyboard interactions
  - deterministic tab behavior for core controls
